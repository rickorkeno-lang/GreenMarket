# routing/ — OSRM (вариант Б, Node-биндинги)

Директория для системы построения маршрутов к продавцам на основе
[OSRM](https://project-osrm.org/) (v26.8.0).

## Статус

- Вариант А (Docker-сервис) удалён: `docker-compose.yml` и `prepare.ps1` больше нет.
- Вариант Б (официальные Node-биндинги [`@project-osrm/osrm`](https://www.npmjs.com/package/@project-osrm/osrm))
  подготовлен к разработке. Функциональный код (Node-сервер, клиентская обвязка) ещё не написан.

## План

1. `npm install @project-osrm/osrm` (native-модуль; на Windows нужен C++ тулчейн:
   Visual Studio Build Tools, CMake, Python).
2. Маленький Node-сервер (например `routing/server.mjs`): загружает индексы из
   `routing/data/` и отдаёт маршруты по HTTP-формату OSRM
   (`/route/v1/driving/{lon1},{lat1};{lon2},{lat2}`), чтобы клиентский код фронтенда
   не зависел от способа запуска.
3. Клиентская обвязка во фронтенде (`src/`): выбор продавца на карте → запрос маршрута
   → отрисовка полилинии в Leaflet.

## Данные

- `data/` — индексированные `.osrm`-файлы для выгрузки OSM «Гессен» (покрывает тестовый
  Франкфурт). Тяжёлые (~1 ГБ), в git не коммитятся (см. `.gitignore` в корне).
- Версия индексов должна совпадать с версией движка (`@project-osrm/osrm` 26.8.0
  соответствует образу OSRM 26.8.0, из которого индексы были собраны).
- Индексы уже построены, заново готовить не нужно.

## Запуск (после реализации)

```bash
npm run routing   # поднимет Node-сервер с маршрутами
npm run dev       # фронтенд
```
